# Like Bach Architecture Decision Records (ADR)

본 문서는 Like Bach 프로젝트의 주요 아키텍처 의사결정과 기술적 대안 검토, 그리고 이로 인한 장점 및 트레이드오프 이력을 명세합니다.

## ADR 001: 하드웨어 이종 환경 대응을 위한 MLX 의존성 격리 및 규칙 기반 엔진 자동 폴백 설계

### 1. 기술적 맥락 및 문제 정의

Like Bach 엔진은 당초 Apple Silicon(macOS) 전용 고속 기계학습 프레임워크인 MLX 및 mlx-lm 라이브러리에 기초한 NeuralBachEngine을 주력으로 설계되었습니다. 그러나 이 설계는 다음과 같은 환경적 제약 사항을 수반합니다.

- 크로스 플랫폼 실행 불가: Windows(사용자의 RTX 5080 개발 환경) 및 리눅스(CI/CD 빌드 파이프라인) 계열의 러너 환경에서는 MLX 라이브러리의 설치가 원천 차단되거나 종속성 설치 오류가 발생합니다.
- 빌드 안정성 위협: 딥러닝 추론용 가중치 파일(bach_model.pt)은 용량이 매우 커서 경량 원격 Actions 러너 환경에 매번 다운로드하거나 포함하여 검증을 돌리기에는 리소스와 시간의 낭비가 큽니다.

따라서 다양한 OS 환경 및 가중치가 누락된 제한적 로컬 환경에서도 파이프라인 오류 없이 전체 웹 어플리케이션과 테스트 스위트가 유기적으로 구동될 수 있는 유연한 대체 추론 아키텍처가 시급히 요구되었습니다.

### 2. 검토된 대안들

- 대안 A: 원격 가상 머신에 항상 모델 가중치와 PyTorch/MLX 전용 추론 API 서버를 띄워두고 원격 API 요청을 날려 테스트하는 방식.
  - 평가: 외부 인프라에 의존하여 가동 비용이 발생하고, 네트워크 장애 시 CI 빌드가 함께 깨지는 치명적인 불안정성을 가집니다.
- 대안 B: CI 빌드 시점에 가중치 파일을 강제로 curl 다운로드하고, MLX 대신 일반 PyTorch로만 추론이 작동하도록 코드를 통째로 리팩토링하는 방식.
  - 평가: 윈도우 환경에서 PyTorch CUDA 구성으로 실행 가능하나, CI 파이프라인 빌드 구동 시간이 수 분 이상으로 지나치게 지연되며 가중치가 변동될 때마다 CI 설정을 갱신해야 하는 번거로움이 있습니다.
- 대안 C (채택): OS 및 종속성 여부에 따라 MLX 모듈 임포트를 조건부로 격리하고, 예외 발생 시 규칙 기반으로 카운터포인트를 연산하는 FugueEngine으로 실시간 전환(폴백)되도록 예외 관리 체계를 단일 정형화하는 방식.

### 3. 최종 결정 및 아키텍처 세부 명세

대안 C를 최종 채택하여 Like Bach 생성 서버의 진입 지점(src/main.py)을 보완했습니다.

- 의존성 조건부 안전 임포트:
  - NeuralBachEngine 모듈을 파일 시작점이 아닌 내부 try-except 블록 안에서 임포트하여, 임포트 에러 발생 시 시스템 붕괴를 일으키지 않고 에러 로깅 후 neural_engine 객체를 None으로 할당합니다.
- 규칙 기반 엔진으로의 실시간 자동 전환:
  - 작곡 요청(POST /compose)이 들어왔을 때 neural_engine이 활성화되어 있지 않으면, 즉시 규칙 기반인 FugueEngine의 compose_full_piece 동작으로 넘어가 연산을 안전하게 대리 처리하고 사용자에게 반환합니다.
- CI/CD 파이프라인과의 통합:
  - 이 폴백 장치 덕분에, 가중치와 GPU가 없는 GitHub Actions Runner 리눅스 환경에서도 pip install -r temp_requirements.txt (MLX 제외 설치) 단계를 성공한 뒤, pytest가 FugueEngine 및 FastAPI 엔드포인트를 아무런 가동 지연 없이 경량 단위 테스트로 통과시킬 수 있게 되었습니다.

### 4. 트레이드오프 및 기대 효과

- 장점:
  - 하드웨어 이식성 극대화: macOS, Windows, Linux, 심지어 GPU가 없는 CPU 단독 초소형 클라우드 서버 인스턴스에서도 Like Bach 백엔드가 무조건 실행됨을 물리적으로 보장합니다.
  - CI/CD 속도 향상: 인공지능 신경망 가중치 다운로드나 모델 전처리 지연이 전혀 없으므로, 원격 빌드 실행 시간이 1분 대 이내로 극단적으로 짧아져 개발 피드백 순환 속도가 향상됩니다.
- 단점/트레이드오프:
  - 모델의 화성 생성 확률 자체를 원격 CI 단에서 종합 테스트해볼 수는 없습니다. 다만 이는 로컬 개발 머신에서 별도로 수행하는 deterministic test 및 시드 테스트 스위트를 도입하여 상호 보완하도록 설계했습니다.
